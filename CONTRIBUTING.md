# Contributing

Thank you for helping improve `s3-multipart-planner`.

1. Search existing issues before opening a new one.
2. For behavior changes, open an issue describing the use case and the S3 or
   compatible-service documentation that supports it.
3. Fork the repository and create a focused branch.
4. Add tests for every behavior change.
5. Run `npm run check` before submitting a pull request.

Pull requests should keep runtime dependencies at zero unless there is a clear,
documented reason to change that constraint. Avoid performance claims without a
reproducible benchmark and environment description.

By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
For vulnerabilities, follow [SECURITY.md](SECURITY.md) instead of opening a
public issue.
